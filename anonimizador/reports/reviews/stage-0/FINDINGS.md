Performance, found while fixing these: the first string parser made the local real-exam run take 71 s instead of 2 s. A Python scan of nested parentheses ran on every `(` in binary data, the same large texts were folded again for each pattern and term, and the e-mail pattern was quadratic on a long run of letters without `@`, which decoded binary strings hold. Nesting is now one regular expression, `fold` is cached, and the e-mail pattern is anchored and bounded. The run takes 5 s. `tests/test_channels.py::test_a_long_run_without_at_sign_is_fast_to_search` guards the pattern; its mutant took 94 s.
