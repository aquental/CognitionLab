Description: Inside an open table, a digit-free line stays a `TableHeader` when `looks_like_header` is true. That predicate is `to_lowercase().contains` over `exame`, `resultado`, `unidade`, `referência`, `referencia`, `valor`, `parâmetro`, `parametro`, and `método`. A `TableHeader` only replaces `header` and is never pushed as a unit. `blank_lines_inside_a_table_keep_its_header` uses `Proteína`, `pH`, `Glicose`, `Hb`, and `Ureia`, none of which contain those substrings.
Impact: A qualitative laboratory row whose text contains one of those substrings is omitted, and every later row of that table is stored under that line as its column header. The source still finishes `Succeeded`.
Reproduction scenario or verifiable rationale: Chunk `Exame | Resultado | Referência` and `Exame parasitológico | Negativo | Negativo` with `WhitespaceTokenCounter` and `budget = None`. Both lines classify as `TableHeader` (three cells, no ASCII digit); the second contains `exame`, so the override does not make it a row. `chunk` returns `Ok` with an empty list. The same call with `Imunidade | Reagente | Não reagente` is empty because `imunidade` contains `unidade`. A following numeric row is emitted with `Imunidade | Reagente | Não reagente` as its header.
Validation suggestion: Treat a digit-free line as a new header only when its cells are header labels, compared as whole cells. Assert that `Exame parasitológico | Negativo | Negativo`, `Método | Colorimétrico | —`, and `Imunidade | Reagente | Não reagente` are each one `TableRow` that still carries `Exame | Resultado | Referência`, including when a blank line separates them from that header.
