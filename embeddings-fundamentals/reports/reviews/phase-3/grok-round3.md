Description: `embed_texts` right-pads every query to `max_len` with `embedder.pad_id` and calls `get_text_features` with the id tensor alone. EmbedAnything 0.7.1's SigLIP text tower (`TextTransformer::forward`) runs the encoder with a null attention mask and returns the hidden state at index `seq_len - 1`. SigLIP's pad id is `text_config.pad_token_id`, distinct from EOS. After the resize, `seq_len` is always the position limit (64), so every query shorter than 64 tokens is pooled at a pad position, and those pad positions take part in full bidirectional attention. CLIP's text tower builds a causal mask and pools `argmax` of the token ids. Its pad id is `<|endoftext|>`, the maximum id, so the same resize leaves CLIP's pooled index on the first end token.
Impact: Every SigLIP query vector used by `search_images` and by the published Phase 3 SigLIP report (`reports/phase-3/comparison.md`, nDCG@3 0.270, space `space-912b12ea1376ca71b44ae24b04fc91ca`) is the pad position's representation. The trained SigLIP pool is the EOS hidden state with pads masked. Image features go through `get_image_features` and are unaffected. The pad position still attends to the real tokens, so scores vary and `a_real_siglip_load` can rank the chest image first for one Portuguese query while the text tower remains wrong.
Reproduction scenario or verifiable rationale: Any synthetic query whose `encode_ids` length is below 64 (the queries in `queries-v1`) is resized so the tensor's last column is `pad_id`. `TextTransformer::forward` reads `seq_len` from that tensor and indexes `seq_len - 1`. The same ids without the extra pads make `seq_len - 1` the EOS id and produce a different vector. The Phase 3 SigLIP run embeds those short queries through this path.
Validation suggestion: For a short query, compare `embed_queries` with a call that stops at the real tokens (sequence already ends in EOS when specials are added) or that pools the last non-pad index. The vectors must match. Assert the pooled index equals the EOS index whenever the unpadded length is below `max_len`. A single-ranking integration check does not catch this.
