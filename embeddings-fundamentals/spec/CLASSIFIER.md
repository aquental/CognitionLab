## 1. Objective and context

The anonymizer (`../anonymizer`) writes, on each run, a Markdown index with one row per exam. The owner wants that index to show **the exam type the classifier identified and the weights (probabilities) of all the alternatives**.

The classifier decides **which of the nine types** (TD §4) a document is, with a **confidence** in [0, 1]. It asks Jev, TypeSafe's System One model, a single `Choice` question about a JSON state that contains only what identifies the type. The personal data that the rules recognize is removed before sending, and a final check blocks sending if anything is left (TD §1, §6–§8).

The production classifier is written in Python, in StealthApp. This document specifies a **Rust port** of the core and of the Jev call, with the same behavior, verifiable byte for byte (TV). It also specifies a single-file CLI and the link to the anonymizer report.

## 3. Privacy: blocking rules

### 3.1 The conflict

The classifier **sends exam text, already masked, to a remote service** (Jev). This crate's `CLAUDE.md` forbids sending the exams in `tests/sample-exams/`, or anything derived from them, "to any remote engine". Running the classifier with sending on these exams is possible only with a written exception from the owner (Q-P1).

**Owner decision (Q-P1, 31/10/2026): sending is allowed only for anonymized copies that passed the `anonymizer` re-verification (`verify` ok), with the double opt-in of R-P1.** Sending the text of the originals is still forbidden. The exception is recorded in `CLAUDE.md`.

Facts behind the decision:
- Masking does not keep what it removes. `Resultado` holds only the masked text and the per-layer counts (TP `mascaramento.py`, class `Resultado`), and `EstadoPreparado` holds only counts (TP `classificador_documento.py`, class `EstadoPreparado`). Nothing that was removed is kept or sent. The port keeps this property (§5.3; invariant 8 in §16).
- Masking removes only what the rules recognize, and it does not guarantee universal anonymization (TD-PRD §2, M4; TD §8, "a conferência não é uma segunda garantia independente", i.e. the check is not a second, independent guarantee). Personal data that the rules do not recognize, such as a name with no label and no honorific in the middle of the text, would be sent along. That is why the input is the anonymized copy: the black boxes from rasterization come before masking.
- TypeSafe states that Jev is not trained on customer requests or responses. Zero data retention (ZDR) is available only to enterprise customers (TS-MOD, "Data handling").

### 3.2 Implementation rules

- **R-P1. Sending only with a double opt-in.** The CLI calls Jev only with the `--enviar` option **and** the variable `CLASSIFIER_REMOTE_ALLOWED=1`. If either one is missing, the result is `preparado` (no sending, like `--sem-envio` in StealthApp, TD §5.4). The crate's equivalent of `remote_allowed` (CLAUDE.md, "Data handling") is checked **before** the key is read and before the HTTP client is built.
- **R-P2. No text in logs or on standard output.** The `tracing` events and the JSON line (§10.3) carry counts, digest, state, type and probabilities, never text, names or the input file name. The exception is `--mostrar-estado`, which prints the masked state and may be used only with synthetic inputs (R-P4).
- **R-P3. The key never appears.** `Debug` and `Display` of the types that hold it redact it. It never goes into error messages, and it is read only after R-P1.
- **R-P4. Tests.** Automated tests use only synthetic inputs. Tests with real exams follow `CLAUDE.md` (`#[ignore]`, `RUN_SAMPLE_EXAMS=1`, properties and counts only) and **never** use `--enviar`.
- **R-P5. Reviewers.** Review packages never carry exams, their text, or the F8 words (§3.4).

### 3.3 The file name

`termos_permitidos` lets through only the terms in `VOCABULARIO_TIPO` (TD §6, step 5, and invariant 4), so the file name and the title never carry a person's name to the provider. Even so, R-P2 applies: the file name does not appear in the output.

### 3.4 The vectors and finding F8

Copying TV into `tests/fixtures/classifier/` publishes it on GitHub, so the rule "synthetic data does not reuse words from exam file names" applies to it. The owner chose (Q-P2, 31/10/2026) to **regenerate the vectors in StealthApp** with other invented names. This was done the same day:
- **Swap:** the two words were replaced with invented names of the same length (`Zanoni` and `Nilo`), keeping case and accent (`Niló`), in 32 occurrences across 5 classifier files. The files were the generator `app/cli/vetores_classificador.py`, the tests `test_mascaramento.py`, `test_classificador_documento.py` and `test_classificar_documento_cli.py`, and TD. The 4-letter word also occurs outside the classifier, in lowercase, as a library name in `security.py` and `requirements.txt`; it was not touched there.
- **How the names were chosen:** none of them occurs in the exam file names, in the classifier vocabulary, or anywhere else in StealthApp.
- **Vectors regenerated:** with Python 3.14, only the 14 input lines changed. Outputs, states and digests stayed identical, because names are masked before any output. The 356 classifier tests in StealthApp pass.
- **Final check:** no word used as a name in the vectors matches the exam file names. Two matches remain with common 7-letter words (used in 15 and 16 StealthApp files), which are not used as names.
- **Commit:** the swap is in StealthApp commit `6cd3dd0`, not yet pushed to the remote. The hashes in §0.1 match it.

### 4.2 Features and dependencies

- **N1** (every module except `jev.rs`) always compiles. It is pure: no I/O, no network and no mutable global state.
- **`classifier-jev = ["dep:reqwest"]`**: the HTTP adapter. `reqwest` is already an optional dependency of the crate (`engine-openai`), with `rustls`.
- New dependencies:

  | Crate | Version | Purpose |
  |---|---|---|
  | `fancy-regex` | `0.19.2` | Lookbehind and lookahead (`(?<=\s\s)`, `(?<=[\t\|;])`, `(?!…)`), which the `regex` crate does not support (TD §18.1). |

  Nothing else: `sha2`, `hex`, `serde_json`, `unicode-normalization`, `tokio` and `thiserror` are already in `Cargo.toml`.
- **Unicode 16.0.0 everywhere.** TV was generated with UCD 16.0.0 (TV `meta.unicode_versao`):
  - `regex-syntax` 0.8.11, which `fancy-regex` uses, is also UCD 16.0.0 (`unicode_tables/perl_word.rs`), but the engine's `\w`, `\d`, `\s` and `\b` classes are **not** used (§6.3);
  - `unicode-normalization` 0.1.26, the version in `Cargo.lock`, is **Unicode 18.0.0**, and 0.1.24 is **16.0.0** (the `UNICODE_VERSION` constant of each version). Phase 0 pins `unicode-normalization = "=0.1.24"` if `pdf-extract` and `stringprep`, which also depend on it, accept that version.
  - Otherwise, `compor` and `dobrar` leave unchanged every code point that is **unassigned in UCD 16.0.0**, by looking it up in a table generated like the ones in §6.3. On that path, `compor` applies NFC **separately to each contiguous run of assigned code points**, and the unassigned ones act as barriers. In UCD 16 they have combining class 0, so a new mark from UCD 17/18 is never reordered together with its neighbors.
  - The two paths differ only for characters added in versions 17 and 18, and the test in §14.4 covers the chosen path.

### 4.3 Conventions (PLAN §2.3 and `rust-skills`)

- No `unwrap`, `expect` or `panic!` outside tests: `Cargo.toml` denies `unwrap_used`, `expect_used` and `panic`.
- **Fixed regexes:** compiled once, without `LazyLock` + `expect`. They live in a `Mascarador`, built by `Mascarador::new() -> Result<Self, ClassifierError>` and passed by reference (`&Mascarador`, `Send + Sync`) to every N1 function that uses a regex. The CLI builds it once, and an error there is reported as an internal error (code 1).
- **Dynamic regexes:** the known-name regexes (`_padroes_conhecidos`) and the `_nomes_dos_indicios` search (§6.4) are compiled per call, and a compilation failure becomes a `ClassifierError`, never a panic.
- Errors use `thiserror` in the library; `anyhow` only in `main`/`cli`. `#[expect(lint, reason = "...")]` instead of `#[allow]`.
- Enums and newtypes instead of strings (`Categoria`, `PaginasModo`, `OrigemTexto`, `EstadoClassificacao`, `ErroCategoria`, `MotivoCodigo`, `Camada`).
- Native `async fn` in traits, without `#[async_trait]`: the provider is not used as `dyn` (PLAN §2.2). The CLI is generic over `P: RlcdProvider`.
- Floats: `f64`; comparisons with `total_cmp`; no `==` between floats outside the tolerances in §7.

### 5.4 Sent state: two serializations

```rust
pub struct EstadoEnviado { pub arquivo: Arquivo, pub paginas_modo: PaginasModo, pub paginas: Vec<PaginaEnviada> }
pub struct Arquivo { pub termos_nome_arquivo: Vec<String>, pub termos_titulo: Vec<String>, pub extensao: String, pub total_paginas: u32 }

```

The same state has **two** serializations, and neither may depend on `#[derive(Serialize)]` or on the `preserve_order` feature of `serde_json`. `Cargo.toml` turns on `preserve_order` in the dev-dependencies, so a test could pass with an order that the binary does not produce.

## 6. Core N1: text, Unicode and regex

### 6.1 `compor` (TD §6, step 0)

`NFC(t)`, then the replacement with `\n` of each occurrence of `\r\n|[\r\x0b\x0c\x1c\x1d\x1e\x85  ]`, in that order. It does not include `\x1f` (TD §18.1, `str.splitlines()`). Vectors: TV `compor`.

**Who composes** is exactly who composes in TP (grep `compor(` in `mascaramento.py` and `classificador_documento.py`, at the pinned commit):
- `remover_dados_pessoais`, on the text;
- `conferir`, on the text, before layer 2;
- `nomes_dos_rotulos`, on the text;
- `partes_de_nome`, on the name;
- `_padroes_conhecidos`, on each known name;
- `termos_permitidos`, as `dobrar(compor(texto))`;
- `montar_estado`, on each `pagina.texto`, at the start.

**Do not compose:** `dobrar` (otherwise `"á"`, with 2 code points, would become `"a"`, which breaks the invariant of §6.2 and the NFD cases of TV `dobrar`), `extract_patient_hints`, `_nomes_dos_indicios`, `_caracteres_uteis` and the `extensao` of `montar_estado`. These receive whatever the caller passes. Inside `montar_estado`, the page text is already composed.

### 6.2 `dobrar` and offsets (TD §7.3, "Primitivas")

- For each `char ch`: `base = NFD(ch)` (**canonical** decomposition, never NFKD), first code point; `baixa = lower_python(base)`; the result is `baixa` if it has a single code point, otherwise `base`.
- `lower_python` is Python 3.14's `str.lower()` for a single character. It can return more than one code point (`İ` → `i̇`), which is why the rule above exists. The table of multi-code-point exceptions comes from the generator (§6.3).
- **Invariant:** `dobrar(t).chars().count() == t.chars().count()`, tested as a property (proptest).
- **Offsets.** Python indexes in code points. `fancy-regex` returns offsets in **bytes**, and `É` (2 bytes) folds to `e` (1 byte). Rule: every span `(inicio, fim)` in N1 is in **code point indices**. `text.rs` provides a `MapaOffsets` (byte → code point) per folded string, and `_substituir` works on a `Vec<char>` or with the map. The 6 000 and 60 000 cuts and `caracteres_enviados` are also in code points (TD §6, step 3).

### 6.3 Python-style character classes (TD §18.1)

The classes of Rust's regex engine do **not** work. Verified on 31/10/2026 with `regex` 1.13.1: `^\w+$` matches `"a\u{301}"` and `"a\u{203f}"`, and in Python 3.14 neither of them is `\w` (TD §18.1).

- `scripts/gen-pyclasses.py` generates `src/classifier/pyclasses.rs`. It holds lists of code point ranges for:
  - the regex classes `\d`, `\w`, `[^\W\d_]`, `[^\W_]` and `\s`;
  - the character predicates `isupper`, `islower`, `isdigit`, `isdecimal` and `isspace`, the titlecase predicate and `iscased`:
    - **titlecase** is category `Lt` (`unicodedata.category(ch) == "Lt"`), the flag that the string-level `s.isupper()` tests in CPython. The single-character `str.istitle()` does not work, because it is also true for uppercase letters (`"A".istitle()`); Phase 1 found this through TDD;
    - **`iscased`** is the Unicode Cased property, which CPython uses in `_PyUnicode_IsCased`; for one character it is `ch.isupper() or ch.islower() or category == "Lt"`;
  - the full `lower()`, `upper()` and `title()` mappings of every character whose result differs from the input, including those with more than one code point (`ß` → `SS`, `İ` → `i̇`, `ǆ` → `ǅ`);
  - **Case_Ignorable**, for the final sigma: CPython's `lower()` and the lowercase branch of `title()` replace `Σ` with `ς` when, skipping Case_Ignorable code points, there is a cased code point before it and none after it (`handle_capital_sigma`; `"ΟΣ".lower() == "ος"`). `unicodedata` does not expose the property, so the generator reads it from `str.lower()` itself. `dobrar` does not use the context: it folds each code point on its own, as TP does (Codex finding C1-1);
  - the set of assigned code points: only on the guarded path of §4.2. It is not generated, because pinning 0.1.24 worked (Phase 0).
- The generator runs with **Python 3.14** and **aborts** if `unicodedata.unidata_version != "16.0.0"`. On this machine, `python3` is 3.15.2, with UCD 17.0.0; 3.14.10 (`/opt/homebrew/bin/python3.14`) has 16.0.0.
- The header of the generated file records the Python version, the UCD and the generator's sha256. A test checks that the generated file matches the generator (as `test_vetores_classificador` does in StealthApp).
- Each ported regex uses these ranges as explicit `[...]` classes, and `\b` becomes `(?:(?<=W)(?!W)|(?<!W)(?=W))`, where `W` is Python's `\w` class. `fancy-regex` accepts fixed-width lookbehind.

## 7. Core N1: JSON, digest and decision

### 7.1 Response validation (TD §9.5; TP `validar_respostas`)

`decisao::validar_respostas(brutas) -> Option<RespostaEscolha>` reproduces TP `rlcd_client.validar_respostas`, restricted to the classifier's `Choice` criterion. The input is TP's **neutral format**, the same as in TV `validar_respostas`, not the Jev wire format:

```
brutas: { <criterio_id>: <bruto> }   where <bruto> is
  { "escolha": <any JSON>, "probabilidades": <any JSON, or absent/null> }  or  <string escolha>
```

In this order:
1. the keys of `brutas` are exactly `{tipo_documento}`;
2. `escolha` is a string among the nine options;
3. if `probabilidades` is `null`/missing, or the raw value is a string, the probabilities become one-hot on the choice (`rlcd_client.py:224–225`). This happens only with the test double: the Jev adapter always delivers a map (§8.4);
4. `probabilidades` is an object and has only keys among the options; missing ones count as 0.0;
5. each value, converted like TP's `_finito` (`float(valor)`: a JSON number, a numeric string, or `true`/`false` as 1.0/0.0), is finite and in [0, 1];
6. `|Σ − 1| ≤ 1e-3` (`TOLERANCIA_SOMA_PROBABILIDADES`), with the sum taken **in the order of `Categoria::TODAS`**, the same as TP (`for op in criterio.opcoes`), so that rounding is identical.

If any check fails: `None`, and the result is `ErroCategoria::RespostaInvalida`. Vectors: TV `validar_respostas` (12). The `_finito` conversion exists only here, for conformance; the Jev wire is decoded strictly before this step (§8.4, DV3).

### 7.2 Decision (TD §10, normative)

```
confianca = probabilidades[escolha]
ordenadas = probabilidades in descending order (total_cmp)
margem    = max(0.0, ordenadas[0] − ordenadas[1])
estado    = Ok if confianca + 1e-9 >= limiar, else Incerto
```

`confianca` is the probability **of the choice**, which may not be the highest one. Jev's `confidence` (TS-API, `ChoiceAnswer.confidence`) is a different measure: a summary of the shape of the distribution, which is 1 when all the probability is on one option and 0 when it is spread evenly (`https://docs.typesafe.ai/confidence.md`). It is stored as `confianca_provedor` (DV7) and does not enter the decision. Vectors: TV `decidir_classificacao` (7), compared with a tolerance of 1e-12 (TD §17.2).

### 7.3 Threshold

`CLASSIFIER_CONFIANCA_MIN`, default `0.70`, accepted only if it is finite and in [0, 1] (TD §16.1). `NaN` is rejected with code 5.

### 7.4 `json_canonico` and digest (TD §11.1)

Equivalent to `json.dumps(x, sort_keys=True, separators=(",", ":"), ensure_ascii=False)`:
- keys sorted by code point, no spaces, non-ASCII written literally in UTF-8;
- escapes `\"`, `\\`, `\n`, `\r`, `\t`, `\b`, `\f`, and `\u00xx` in lowercase hex for the other control characters below 0x20;
- U+007F, U+2028 and U+2029 without escaping;
- integers in decimal; the state has no floats.

Then `sha256` of the UTF-8 bytes. The string escaping of `serde_json::to_string` matches Python's (verified: `"\u{1f}\u{7f}\u{2028}"` becomes `"\u001f` + literal U+007F + U+2028), so it can be used for **each string**.

`canonico::json_canonico(v: &serde_json::Value) -> String` works for **any** `Value`, as in TP and TV `json_canonico`, where the cases are arbitrary objects. It walks the value recursively and, in each `Value::Object`, collects the keys and **sorts them explicitly** by code point (`str::cmp` in Rust sorts by UTF-8 bytes, which gives the same order). This way the order does not depend on `preserve_order`. Integers are written in decimal. A float is written like Python's `repr`, which is what `json.dumps` writes: the shortest digits that round-trip to the same float, with ties going to the even digit; scientific notation with a sign and at least two exponent digits when the decimal exponent is below −4 or above 16 (`1e-05`, `1e+16`); otherwise positional, with `.0` when there is no fractional part (`1.0`, `-0.0`). `serde_json` writes a different format (`1e-9`, `1e16`). The state has no floats, and neither does TV `json_canonico`; an optional differential compares with Python (Codex finding C1-2). The state digest is `sha256(json_canonico(&estado_como_value))`.

**Do not reuse `ids::canonical_json`.** It normalizes every string and every key to NFC (`src/ids.rs`, `write_string`), and Python does not normalize. `extensao` goes only through `dobrar`, without `compor` (TD §6, step 5), and can contain a loose combining mark, which NFC would join to the previous letter, changing the digest. Vectors: TV `json_canonico` (3) and the digests of TV `montar_estado`.

## 8. Jev adapter (N2, feature `classifier-jev`)

### 8.1 Identity

- `provider = "typesafe"`.
- `adapter_version = "cognitionlab-jev-http/1"`: specific to the port and different from `typesafe-sdk-0.7.4/1` (TD Q5). It moves to `/2` on any change to the wire format or to response handling.
- `model`: `RLCD_MODEL`, default `jev-1.13.0`. It must match `^jev-\d+\.\d+\.\d+$` (TD §16.1, `modelo_rlcd_fixo`), tested after `strip()`; the value sent is the configured one. An alias (`jev-latest`, `jev-preview`) is refused with code 5, because an alias changes without notice and invalidates the calibration (TS-MOD, "Aliases"; TP `typesafe.py`).

### 8.2 Request

- `POST {base}/v1/systemone`, with `base = RLCD_BASE_URL` or the default `https://api.typesafe.ai`. The URL is built by string concatenation, after removing one trailing `/` from `base`, never with `Url::join` (TD §9.3).
- Headers: `Authorization: Bearer <chave>`, `Content-Type: application/json`, `Accept: application/json`, and `User-Agent: cognitionlab-classifier/<versão do crate>`. The SDK also sends its own SDK and runtime headers (`transport.py`), which this port does not imitate. It does **not** send `TypeSafe-Danger-Zone-Long-Context` or `Content-Encoding`.
- Body: compact, UTF-8 without BOM, with keys in this order, which is the SDK's order (`endpoints.py`, `prepare_system_one`):

  ```json
  {"state":<state in wire format, §5.4>,
   "model":"<RLCD_MODEL>",
   "questions":{"tipo_documento":{"type":"choice","instructions":"<PERGUNTA>",
                                  "criteria":{"vop":"<description>", …, "outro":"<description>"}}}}
  ```

- **The order of `criteria` is the order of `Categoria::TODAS`**, and it is mandatory: Jev 1.13 leans toward the first option (TS-JAG #8), and the StealthApp calibration used this order. A test checks the body **bytes** with the `preserve_order` feature on and off.
- `state` is a JSON object (TS-API accepts a string, an object or an array). It is not the canonical JSON string, which only OpenAI received (TD §9.3).
- Limits: the body stays far below 32 MiB (TS-ERR). The state has at most 60,000 code points of text, about 17,000 tokens (TD-PRD §6.6), below 32k tokens per question and 64k per request (TS-MOD). The port does not count tokens. A `400` with `max_tokens_exceeded` falls into `resposta_invalida`.

### 8.3 Timeout, concurrency and cancellation (TD §9.4)

- `avaliar = tokio::time::timeout(RLCD_TIMEOUT_S, async { adquirir o semáforo; fazer o POST; ler o corpo })`. The wait for the semaphore counts inside the timeout, as in Python (TD §9.3). Default: 20 s.
- A semaphore with `RLCD_MAX_CONCURRENCY` slots (default 4). The CLI uses 1 (TD §9.3).
- The total timeout is the `tokio` one. The `reqwest` client has no timeout of its own (neither `timeout` nor `connect_timeout`), so that only one clock decides. Even so, a `reqwest::Error` with `is_timeout()` is mapped to `timeout` (§8.5).
- Cancellation: a cancelled Rust future is dropped. No code swallows the drop, and there is no `catch_unwind`. This is equivalent to "`CancelledError` propagates" (TD §15).
- **No retry.** TS-ERR recommends exponential backoff on `429`/`529`, but the Python classifier turns retry off (`RetryPolicy(max_retries=0)`), and an error is only retried on the next run (TD §15). The port keeps this.

### 8.4 Response 200

Decoding has two stages: the **envelope**, by the TS-API and SDK schema, and then the **validation** of §7.1. In SDK 0.7.4, `SystemOneResponse` requires `model`, `answers` (at least 1) and `usage`, and `ChoiceAnswer` requires `type`, `choice`, `confidence` and `probabilities` (`_schemas/models.py`).

1. **Envelope**, with `serde`, without `deny_unknown_fields` (the service is external and may add fields):
   ```rust
   struct RespostaFio { model: String, answers: BTreeMap<String, serde_json::Value>, usage: UsoFio }
   struct UsoFio { input_tokens: u64, output_tokens: u64 }
   ```
   `answers` is a **map**, not a struct, so that an extra answer reaches rule 1 of §7.1 instead of being dropped by `serde`. `usage` and its two fields are required, as in the SDK: if it is missing, the response is invalid. (TD §9.3 says "if missing, it becomes `None`", but that describes the adapter's `getattr`, which the SDK's pydantic never lets through without `usage`.)
2. **Conversion to the neutral format** (`jev.rs`): for each `(id, valor)` in `answers`:
   - if `valor` is an object with `type == "choice"`, a string `choice`, a number `confidence` and a `probabilities` object of numbers, the raw value is `{"escolha": choice, "probabilidades": probabilities}` and `confianca_provedor = confidence`;
   - any other shape (`type` of another primitive, a non-string `choice`, or `probabilities` missing, `null` or with a non-numeric value) becomes the raw value `{"escolha": null, "probabilidades": {}}`, which rule 2 of §7.1 refuses. It **never** becomes one-hot.
3. **Validation** (§7.1) on the neutral format.

| Situation | Result | Metadata kept |
|---|---|---|
| Body that is not JSON, or envelope outside the schema (`model` missing, `answers` empty or missing, `usage` missing, wrong type) | `resposta_invalida` (TD Q8, recommendation; DV3) | `latencia_ms`, `provider_request_id` from the header (DV8); `model` = the requested one; `uso` = `None` |
| Envelope ok, conversion or validation fails (extra answer, `tipo_documento` missing, `type` other than `choice`, choice outside the options, wrong sum) | `resposta_invalida` | echoed `model`, `uso`, `latencia_ms`, `provider_request_id` (TP `montar_resposta`) |
| Envelope ok and validation ok | `Ok(RespostaEscolha)` | all of them, plus `confianca_provedor` |
| Header `x-typesafe-request-id` | `provider_request_id`. Missing: `None`, **without** an error (DV2) | — |

### 8.5 Transport errors

Tested in this order; the first true condition decides. It is the same order as the SDK, which tests `TimeoutException` before `RequestError` (`transport.py`).

| # | Situation | Category |
|---|---|---|
| 1 | The `tokio::time::timeout` expired, in any phase (semaphore queue, connection, sending, reading), or a `reqwest::Error` has `is_timeout()` | `timeout` |
| 2 | DNS, connection, TLS or body-read failure (`reqwest::Error` with `is_connect()`, `is_request()` or `is_body()`; and any `bytes()` error while reading a 200, which `reqwest` marks as `is_decode()` when the body is cut short, even though nothing is decoded there) | `rede` |
| 3 | Any other `reqwest::Error` | `outro` |

### 8.6 HTTP status (TD §9.3, TS-ERR)

| Status | Category |
|---|---|
| 401, 403 | `autenticacao` |
| 429 | `quota_provedor` |
| 400 (includes `max_tokens_exceeded`), 422 | `resposta_invalida` |
| 404, 413, 415, 5xx (includes 529 `Overloaded`), any other non-2xx | `outro` |
| 2xx other than 200 | `outro` (TS-API only defines 200) |

The error body is **not** logged, because it may echo the `state` (TS-API, `ValidationError.input`, "Text preview of the rejected input"). Only the status and the category go to the log.

## 9. `classificar` (TD §9.1)

### 9.1 Decision order

```
prep = montar_estado(entrada, modo)
1. prep.sem_conteudo()      → SemConteudo, motivo TextoInsuficiente if prep.texto_insuficiente() else SemConteudo; no call
2. !prep.bloqueio.is_empty() → BloqueadoPrivacidade, motivo ConferenciaPrivacidade,
                               mascaramentos += {"conferencia_<camada>": n}; no call
3. sending not authorized (R-P1) → Preparado (motivo EnvioNaoAutorizado if --enviar was asked); no call
4. otherwise                 → request (§9.2), avaliar (§8.3);
                               error → Erro, erro_categoria, motivo ProvedorErro;
                               ok    → decidir (§7.2), tipo = escolha, probabilidades copied
```

Step 3 takes the place of TD's "test double not allowed" step (DV5). Steps 1 and 2 come **before** the authorization, so `preparado` always means "would be sent".

### 9.2 Minimization invariant

The state sent has only `arquivo.{termos_nome_arquivo, termos_titulo, extensao, total_paginas}`, `paginas_modo` and `paginas[].{n, texto}` (TD §17.1, invariant 3). The types of §5.4 guarantee this by construction, and a test checks that no key of the state is in `CHAVES_PROIBIDAS_NO_ESTADO` (copied from TP `rlcd_client.py`).

## 10. CLI `classify`

### 10.1 Usage

```
embeddings-fundamentals classify <file> [--paginas 1|2|todas] [--json] [--enviar] [--limiar X]
                              [--titulo T] [--nome-paciente N]... [--mostrar-estado]
```

**Build dependency for sending:** only a binary built with the `classifier-jev` feature (`cargo build --release --features classifier-jev`, or `cargo run --features classifier-jev -- classify …`) can send to Jev. The feature is off by default. Without it, authorized sending (`--enviar` with `CLASSIFIER_REMOTE_ALLOWED=1`) gives `erro`, code 5 (`configuracao_invalida`), without reading any step 3 variable and without sending anything (§12). Without `--enviar`, both binaries behave the same (`preparado`). This also applies to the binary that `anonymizer batch --classifier` calls (§11.1).

The default for `--paginas` is `CLASSIFIER_PAGINAS`, or `"2"` (TD §16.1). With `--json` the output is one JSON line; without it, readable text with the same fields and no exam text.

`--mostrar-estado` adds `estado_preparado` (the state in wire format) **only** when `estado ∈ {preparado, ok, incerto, erro}`, `prep.bloqueio` is empty and `!prep.sem_conteudo()` (TP `classificar_documento.py:369`). In `bloqueado_privacidade` the state contains exactly the personal data that the check found, so the key is **absent** from the JSON and the readable mode does not print it. The option exists only for synthetic inputs (R-P4).

**Execution order** (that of TP `_executar`, adapted):
1. validate `--paginas`/`CLASSIFIER_PAGINAS` and the threshold (code 5, `configuracao_invalida`);
2. the file exists (code 2, `arquivo_inexistente`) and the extension is supported (code 2, `formato_nao_suportado`);
3. if sending is authorized (R-P1: `--enviar` **and** `CLASSIFIER_REMOTE_ALLOWED=1`): validate `RLCD_MODEL` (code 5, `modelo_invalido`), the key (code 5, `sem_chave`), `RLCD_BASE_URL`, `RLCD_TIMEOUT_S` and `RLCD_MAX_CONCURRENCY` (code 5, `configuracao_invalida`), and build the client. Without authorization, **none** of these variables is read or validated;
4. check the tools: `pdfinfo`, `pdftotext` and `pdfimages` for PDF; `tesseract` with the `por` language for images. In a PDF, `tesseract` is checked on the first page that needs OCR, before calling it. If any is missing, code 5, `ocr_indisponivel`;
5. extract (§10.2). A failure to read the file gives code 2 (`arquivo_ilegivel` or `limite_pdf`);
6. `montar_estado` and `classificar` (§9.1).

Any other unexpected error: code 1, `erro_interno`.

### 10.2 Input

| Format | Pages |
|---|---|
| `.pdf` | Up to 200 pages (`MAX_PDF_PAGES` from `pdf_extract.py`); above that, code 2 (`limite_pdf`). Each page's text is `PageText::text()` from the crate's `TextExtractor` (poppler `pdftotext`), with no extra `strip()`, with origin `nativo`. On the pages selected by the mode, with `nativo = strip_python(texto)`, OCR runs (`OcrEngine::ocr_page`) when `nativo` is empty, or when the page is visual (§10.4) and `nativo` has fewer than 220 code points (`TEXT_SPARSE_CHARS`). If OCR returns text whose `strip_python()` is not empty, the page becomes `"\n".join(t for t in (nativo, strip_python(ocr)) if t)`, with origin `ocr_local`. An OCR error on a page leaves the page as it was (TP: `ValueError` → `continue`). |
| `.png`, `.jpg`, `.jpeg` | First the image is decoded with the `image` crate, already a dependency; if that fails, code 2 (`arquivo_ilegivel`). Then one page `n = 1` with the OCR text of the image, origin `ocr_local` (TD §5.2, branch "outra extensão"). With no text there is no page, and the result is `sem_conteudo` (code 3). This is the format of an anonymized image copy. |
| other | Code 2 (`formato_nao_suportado`). Unlike StealthApp, there is no DOC/DOCX/ODT conversion through LibreOffice. |

**OCR.**
- **Configuration:** the classifier's extraction uses its own `ExtractionConfig`, with `ocr_lang = "por"`, StealthApp's language (`ocr_local.IDIOMA`). The other fields (`ocr_dpi`, `ocr_psm`) keep the crate default.
- **Text:** it is the crate's `PageText::text()`, whose lines already come without trailing spaces (`poppler.rs`). The difference from StealthApp's `pytesseract.image_to_string` is covered by DV4.
- **Standalone image:** the `OcrEngine` trait only reads PDF pages (`ocr_page(pdf, page)`). Phase 5 adds to the crate's tesseract engine a method `ocr_image(&self, image: &Path) -> Result<PageText, ExtractionError>`, which calls tesseract directly on the already validated image. It stays outside the trait, so that `FixtureExtractor` does not have to implement it; the CLI test double has its own.

- `nome_arquivo` is the file name with the extension; `titulo` is `--titulo` or the name without the extension; `extensao` is the lowercase suffix, without the dot (TD §5.3). `total_paginas` is `len(paginas)` (TD §5.2). `nomes_conhecidos` are the `--nome-paciente` values.
- A missing tool is checked **before** extraction (§10.1, step 4), so an `ExtractionError` during extraction is always treated as an unreadable file (code 2). The two cases are never confused.

### 10.3 Output and codes

The exit codes are those of TD §5.4: 0 (`ok`, `incerto`, `preparado`), 1 (internal error), 2 (input), 3 (`sem_conteudo`), 4 (provider `erro`), 5 (configuration: invalid key, model, OCR, mode or threshold), 6 (`bloqueado_privacidade`). Missing authorization is **not** an error: it gives `preparado` and code 0.

With `--json`, exactly one line goes to stdout, also on errors, with the keys:

```
estado, codigo_saida, envio_realizado, provider, model, adapter_version, perguntas_versao, mascaramento_versao,
origens_texto, paginas_modo, total_paginas, paginas_enviadas, caracteres_enviados, truncado, mascaramentos,
termos_nome_arquivo, entrada_digest, tipo, rotulo, confianca, margem, limiar_aplicado, probabilidades,
confianca_provedor, erro_categoria, motivo_codigo, latencia_ms, provider_request_id, uso
```

- Differences from the StealthApp CLI (TD §5.4): **no** `arquivo` (R-P2: the file name of a real exam may contain the patient's name) and no `simulado`, because there is no test double in the binary. **With** the identity keys, `rotulo`, `limiar_aplicado`, `confianca_provedor` and `uso`.
- **Error envelope before classification** (like TP's `_envelope`):
  - when the CLI stops in steps 1 to 5 of §10.1, the line has `estado = "erro"`, the step's `codigo_saida` and `motivo_codigo` from `MotivoCli` in `snake_case`;
  - `envio_realizado = false`, `origens_texto = []`, `mascaramentos = {}`, `termos_nome_arquivo = []` and `probabilidades = {}`;
  - `null` in `paginas_modo` (except after step 1), `total_paginas`, `paginas_enviadas`, `caracteres_enviados`, `truncado`, `entrada_digest`, `tipo`, `rotulo`, `confianca`, `margem`, `confianca_provedor`, `erro_categoria`, `latencia_ms`, `provider_request_id` and `uso`;
  - `provider = "typesafe"` and the version keys (`adapter_version`, `perguntas_versao`, `mascaramento_versao`) always filled in; `model` filled in only if step 3 ran; `limiar_aplicado` filled in after step 1.

  The line struct (`LinhaCli`) is **separate** from `Classificacao`, with these fields as `Option`. `Classificacao` still has no `Option` on the fields that always exist after `montar_estado`.
- **No path and no raw message.** The readable mode and stderr state only the reason (`arquivo_ilegivel`, `ocr_indisponivel`…) and one fixed sentence per reason. Never the file path, nor the text of an `io::Error`, a tool error or a parser error, which may contain the path or excerpts of the document. TP includes `{caminho}` and `{exc}` in these messages (`classificar_documento.py:147,313,374`); here that is forbidden (invariant 5). The same applies to `tracing` events.
- `envio_realizado` is true if the state is `ok` or `incerto`, or if `motivo_codigo == provedor_erro` (TD §5.4).
- stdout carries only the JSON line. Unlike Python's PyMuPDF, poppler and tesseract run as child processes with stdout captured, so there is no need to redirect fd 1.

### 10.4 Visual page (deliberate divergence DV4)

StealthApp decides whether a page is visual with PyMuPDF (`pdf_extract._is_visual`): images that add up to ≥ 2% of the page area, or vector drawing on a page with fewer than 220 characters. With poppler, the port uses only the image rule:
- `pdfimages -list -f N -l N <pdf>` lists the images on page N. Rows whose `type` is `image` or `stencil` count. According to `man pdfimages`, `stencil` is "a monochrome mask image used for painting a color or pattern", that is, content painted on the page, such as a 1-bit scan. `mask` and `smask` "immediately follow the image" whose transparency they are, and adding them would count the same area twice. The area of each image is `(width / x-ppi × 72) × (height / y-ppi × 72)` in points²;
- the page area comes from `pdfinfo -f N -l N <pdf>`, line `Page N size: W x H pts`, as `W × H`;
- the page is visual if the sum of the areas is ≥ 2% of the page area (`MIN_IMAGE_AREA_RATIO` from `pdf_extract.py`);
- an inspection failure (tool error, output that cannot be parsed, `x-ppi` or `y-ppi` equal to 0, page area 0) treats the page as **visual**, like TP: "it is cheaper to render needlessly than to lose content" (`pdf_extract._is_visual`).

It does **not** detect vector drawing. For this reason the port's input and digest may differ from those of the StealthApp CLI for the same PDF. Conformance is measured at N1 (TV), not at extraction.

## 11. Integration with the anonymizer report (Phase 6)

### 11.1 Where and when

- `anonymizer batch` gets the option `--classifier <binário>` (the already built `embeddings-fundamentals`, with `classifier-jev`). Without it, the report comes out **exactly** as it does today: without the new columns, without the header line and without the `classifier/` directory.
- With it, `start()` also creates `<run>/classifier/` and includes it in the `uncommittable` probes, as it already does with `run.copies` and `run.logs` (`batch.py`, `start`).
- It classifies **the anonymized copy**, not the original, and only when the copy's re-verification gave `ok` (`anonymized_status`). A copy that failed verification is never classified. Rationale: defense in depth, with Jev's masking on top of a rasterized copy that already has no text, no metadata and none of the `verify` findings.
- It calls `<binário> classify --json [--enviar] <cópia>` as a child process, without a shell, with a timeout of `2 × (RLCD_TIMEOUT_S + 5) + 5` seconds, the same formula as the stage ceiling in TD §12.2. `--enviar` is passed only if `batch` itself received `--classify-remote`, and the child process still requires `CLASSIFIER_REMOTE_ALLOWED=1` (R-P1).
- **A classifier failure never fails the anonymization** (analogous to TD §17.1, invariant 1). A child-process timeout, a failure to start it, stdout that is not exactly one valid JSON line, or an exit code that differs from the line's `codigo_saida` or does not fit its state (`ok`, `incerto` and `preparado` with 0; `sem_conteudo` with 3; `bloqueado_privacidade` with 6; `erro` with 1, 2, 4 or 5) become the cell `error: classifier failed` (§11.2). A valid CLI `erro` (1, 2, 5) shows its `motivo_codigo`, as in the table of §11.2. In the previous version, this paragraph said "outside {0, 3, 4, 6}" and contradicted the table. The exit code of `batch` does not change.

### 11.2 What goes into the index

The index (`batch.index`) gets the columns **Exam type (classifier)** and **Weights**, after "Verify anonymized":

| Situation | Exam type (classifier) | Weights |
|---|---|---|
| `ok` | `<rotulo> (<confianca>)` | the nine alternatives, from highest to lowest: `Eco avançado 0.930 · Eco convencional 0.040 · … · Outro 0.004` |
| `incerto` | `uncertain: <rotulo> (<confianca>)` | same |
| `preparado` | `not sent` | — |
| `sem_conteudo` | `no content` | — |
| `bloqueado_privacidade` | `blocked (privacy check)` | — |
| provider `erro` (code 4) | `error: <erro_categoria>` | — |
| CLI `erro` (codes 1, 2, 5) | `error: <motivo_codigo>` | — |
| child-process failure (§11.1) | `error: classifier failed` | — |
| copy not classified, because verification failed or there is no copy | `—` | `—` |

- `<confianca>` and the weights use 3 decimal places and a dot, because the index is in English, like the rest. Ties in the weights are broken by the order of `Categoria::TODAS`.
- **Header:** it gets a line with `provider`, `model`, `adapter_version`, `perguntas_versao`, `mascaramento_versao`, threshold and page mode, taken from the **first** valid JSON line of the run, and it says whether sending was requested. If no copy produced a valid JSON line, the line says `Classifier: no result` and whether sending was requested. The binary path does not appear.
- **Saved JSON line:** the line for each copy goes to `<run>/classifier/<stem da cópia>.json` (for example `exam-<digest>.json`, the same neutral name as the copy, with `.json`), through `write_new` with the anonymizer's git check. The cell links to it. It has no text (R-P2). An invalid line is not saved.

The column names and the weights format are presentation decisions of this document. The owner may change them (Q-C2).

## 12. Configuration

Read from environment variables, with the `.env` at the crate root through `dotenvy`, already a dependency. The `.env` files are read without changing the process environment, in this order of precedence:
1. the process environment;
2. the `.env` found from the current directory upward (`dotenvy::dotenv_iter`);
3. the `.env` at the crate root, so that `anonymizer batch --classifier`, run from another directory, also finds the key.

**`CLASSIFIER_REMOTE_ALLOWED` counts only in the process environment and is never read from a `.env`.** With the key in a file, the authorization to send remains an explicit act of each run (R-P1). `.env.example` has a slot for the key (`TYPESAFE_API_KEY=`). No key value is ever printed.

A binary built **without** the `classifier-jev` feature has no way to send: with sending authorized, it exits with code 5 (`configuracao_invalida`), without reading any step 3 variable.

| Variable | Default | When it is read | Validation (code 5, with the given reason, if invalid) |
|---|---|---|---|
| `CLASSIFIER_PAGINAS` | `2` | always | ∈ {`1`, `2`, `todas`} (`configuracao_invalida`) |
| `CLASSIFIER_CONFIANCA_MIN` | `0.70` | always | finite, in [0, 1] (`configuracao_invalida`) |
| `CLASSIFIER_REMOTE_ALLOWED` | absent | always | **never an error**: only the exact value `1` authorizes (R-P1); any other value, or absence, counts as "not authorized" and gives `preparado` |
| `RLCD_MODEL` | `jev-1.13.0` | only with authorized sending | `^jev-\d+\.\d+\.\d+$` after `strip()` (`modelo_invalido`) |
| `RLCD_API_KEY`, `TYPESAFE_API_KEY` | — | only with authorized sending | `RLCD_API_KEY` takes precedence, and `TYPESAFE_API_KEY` applies when it is empty (TD §16.1). Both empty: `sem_chave` |
| `RLCD_BASE_URL` | `https://api.typesafe.ai` | only with authorized sending | empty or whitespace-only means the default (TD §16.1 has `""` as the default). Otherwise, an absolute `https` URL, or `http` with host `127.0.0.1` or `localhost`, accepted **in the binary**, because Phase 5 tests the CLI against the local server (`configuracao_invalida`) |
| `RLCD_TIMEOUT_S` | `20.0` | only with authorized sending | finite, > 0 (`configuracao_invalida`) |
| `RLCD_MAX_CONCURRENCY` | `4` (CLI: 1, fixed) | only with authorized sending, outside the CLI | integer ≥ 1 (`configuracao_invalida`) |

### 14.2 Properties (proptest, already a dev-dependency)

- `dobrar` preserves the code point count.
- Removal is **not** idempotent in TP (F9, §0.4): the differential test (§14.3) compares the second pass with TP's, and a test pins the F9 example.
- The marker never carries part of the value: after removing a synthetic known name, no part of it with 3 or more letters remains in the text, also when the pieces are glued to each other, to digits or to `_` (DV10; in TP the glued name escapes, F10).
- Determinism: the same input gives the same state and the same digest.
- Limits: `caracteres_enviados ≤ 60,000`, each page ≤ 6,000, and `truncado` consistent.
- `json_canonico` does not depend on insertion order, with `preserve_order` on.

### 14.3 Differential test against Python (optional, local)

`RUN_DIFFERENTIAL=1 STEALTHAPP_DIR=… cargo test --test classifier_differential -- --ignored` generates random synthetic texts: labels, invented names, dates, numbers and Unicode from the hard classes (NFD, `İ`, `ı`, U+2028, `²`, `‿`). It runs `remover_dados_pessoais` and `montar_estado` in StealthApp's Python 3.14 and in Rust and compares them. It never uses real exams.

### 14.4 Unicode

Tests with the trap characters: `İ`/`ı` under IGNORECASE, in literals and in class ranges (`[A-Z]`, `[A-Za-z]`) (§6.4); `ch.isupper()` of the initial only × `s.isupper()` of the string (`"Dr. João Silva"` removed; `"JOÃO DA SILVA"` becomes `"João Da Silva"` in `extract_patient_hints`); `title()` with `ª`/`º` (uncased letters) and with `ǆ`; `upper()` with `ß`; combining marks and `‿` outside `\w`, `²`/`½`/`Ⅻ` in `[^\W\d_]`, U+001C to U+001F in `\s`, and `\x1f` outside `compor`. Also a code point assigned only in UCD 17 or 18, to pin the path chosen in §4.2.

### 14.5 HTTP adapter (no network)

A local test HTTP server (a `tokio::net::TcpListener` on `127.0.0.1`, with no new dependency) covers:
- **200 ok:** checks the headers, the body **byte for byte** (order of `criteria` and of `state`) and the decision;
- **200 without the request id header:** `None` (DV2);
- **200 invalid:** non-JSON body; `usage` missing; `answers` empty; `answers` with an extra answer besides `tipo_documento` (must give `resposta_invalida` with `model` and `uso` preserved); wrong `type`; `probabilities` missing, `null`, empty or with an unknown key; sum 0.98; `NaN` as a string; a number as a string;
- **`reqwest` timeout:** an error with `is_timeout()` becomes `timeout`, not `rede`;
- **status:** 400, 401, 403, 404, 413, 415, 422, 429, 500, 529 and 204;
- **timeout:** the server sleeps past the deadline, and also the wait in the semaphore queue;
- **connection refused:** closed port;
- **security:** the key does not appear in `Debug`, in errors or in logs (with a test `tracing-subscriber`); the body of an error is not logged.

## 15. Non-functional requirements

- **Purity and concurrency:** N1 is `Send + Sync`, with no I/O and no mutable global state. The fixed regexes are compiled once, in the `Mascarador` (§4.3), and N1 can run on several threads over the same `&Mascarador`.
- **Memory:** each text sent has at most 60,000 code points. The name search scans the text of all pages, up to 200.
- **Latency:** bounded by `RLCD_TIMEOUT_S` per call. There is no target for N1 (TD Q6). Phase 3 measures `montar_estado` over the 21 TV cases and a synthetic 200-page document, and records the result without a gate.
- **Determinism:** the same input and the same mode give the same state, the same digest and the same request bytes.

## 16. Port invariants

1. Jev is never called with `sem_conteudo`, with a block, or without the R-P1 authorization.
2. The state sent has only the keys of §9.2. The file-name and title terms come only from `VOCABULARIO_TIPO`.
3. N1 reproduces TV byte for byte. Any change to masking requires a new `MASCARAMENTO_VERSAO`, made in StealthApp. The only exception is DV10 (§13), decided by the owner, which has its own version (`MASCARAMENTO_VERSAO_PORTE`) and changes no TV case.
4. `criteria` goes in the order of `Categoria::TODAS`, and `state` in construction order, whatever the `serde_json` features are.
5. Logs, output and report never contain exam text, a person's name, the input file name, the key or a provider error body.
6. A classifier failure never fails the anonymization.
7. The key is read only after sending is authorized.
8. No structure keeps the values removed by masking: only the masked text and the counts (TP `Resultado`, `EstadoPreparado`).

## 17. What a Rust implementer needs to know (checklist)

- [ ] Read TD §6–§10 in full before writing N1. This document only says how to port.
- [ ] Offsets in code points, with the byte → code point map (§6.2).
- [ ] Character classes generated from Python 3.14 with UCD 16.0.0, never `\w`, `\d`, `\s`, `\b` or `char::is_*` (§6.3).
- [ ] `unicode-normalization` on UCD 16.0.0, or with the guard for unassigned code points (§4.2).
- [ ] `pos` without slicing; `$` as `\n?\z` in the layer 4 filters; `[iIİı]` in IGNORECASE regions (§6.4).
- [ ] Python text of each regex checked against TV (§6.4).
- [ ] Lists and sets copied from TV by a test, not retyped (§6.5).
- [ ] `_substituir` with the order `(início, fim, texto)`; counts before discarding; layers 2 and 4 in sequence (§6.5).
- [ ] Order remove → check the whole page → cut, with `_sem_marcador_partido` (§6.7).
- [ ] Own `json_canonico`, without NFC; two hand-written serializations (§5.4, §7.4).
- [ ] Sum of probabilities in category order; tolerances 1e-3 and 1e-9 (§7).

- [ ] `answers` decoded as a map; envelope × validation, with the metadata preserved for each case (§8.4).

- [ ] `ch.isupper()` of the initial only in `_parece_nome`/`_fim_do_nome`; string `s.isupper()`, `title()` and `upper()` only in `extract_patient_hints` (§6.4).

- [ ] `estado_preparado` never on a block or on `sem_conteudo`; CLI error envelope with `MotivoCli`; messages without paths (§10).
